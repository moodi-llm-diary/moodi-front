# GOAL — ChatGPT·Notion형 사이드바와 Apple 디자인 감성을 결합한 Moodi 전면 재설계

## 0. 목표

현재 Moodi의 UI와 CSS를 전면 재설계한다.

이번 작업은 기존 화면의 색상이나 여백을 부분적으로 수정하는 작업이 아니다.

현재 발생한 다음 문제를 근본적으로 해결한다.

* 페이지마다 색상이 서로 어울리지 않는다.
* 감정별 색상, 카드 색상, 배경색이 충돌한다.
* 일부 CSS가 깨지거나 예상하지 않은 스타일이 적용된다.
* 기존 스타일 위에 override가 누적되어 있다.
* 컴포넌트별 spacing, radius, typography가 일관되지 않다.
* 모바일과 데스크톱에서 서로 다른 디자인처럼 보인다.
* 감성을 표현하려고 여러 색과 장식을 사용하면서 전체 제품의 통일감이 사라졌다.
* 에디터, 기록 목록, 홈 화면이 서로 다른 서비스처럼 보인다.

새 Moodi는 다음 조합으로 완성한다.

```text
앱 구조와 내비게이션:
ChatGPT + Notion

에디터 경험:
Notion 계열의 문서형 블록 에디터

전체 시각 언어:
Apple이 추구하는 절제된 소비자용 제품 디자인

제품 성격:
따뜻하고 개인적인 감성 일기장
```

기존 데이터 모델, API, 인증, 저장소, 일기 CRUD와 같은 비시각적 로직은 보존한다.

레이아웃, CSS, 디자인 토큰, 앱 셸과 UI 컴포넌트는 기존 구현을 보존해야 한다고 가정하지 않는다.

# 2. 제품의 최종 인상

완성된 Moodi는 다음처럼 느껴져야 한다.

* 고급스럽지만 과시적이지 않다.
* 단순하지만 비어 있지 않다.
* 따뜻하지만 색이 과하지 않다.
* 문서 편집기처럼 쓰기 편하다.
* 개인 일기장처럼 사적이고 편안하다.
* 데스크톱에서는 정돈된 생산성 앱처럼 동작한다.
* 모바일에서는 자연스러운 소비자용 일기 앱처럼 동작한다.
* 화면을 처음 봤을 때 기능보다 사용자의 기록이 먼저 보인다.

* UI 요소들이 서로 경쟁하지 않는다.

다음처럼 보이면 실패다.

* 여러 파스텔 색상이 무작위로 섞인 화면
* beige, pink, purple을 반복한 일반적인 감성 템플릿
* Apple 웹사이트를 흉내 낸 랜딩 페이지
* Notion을 색만 바꾼 복제품
* ChatGPT와 동일한 채팅 앱
* IDE
* 관리자 대시보드
* 파일 탐색기
* 작은 카드가 빽빽하게 반복되는 화면
* 텍스트 한 줄과 거대한 여백만 있는 화면
* 글래스 효과가 과도한 UI
* 페이지마다 색상과 radius가 달라지는 화면

# 3. 기존 CSS 처리 원칙

현재 CSS가 일부 깨지는 문제를 먼저 해결한다.

기존 스타일 위에 새로운 override를 추가하는 방식으로 작업하지 마라.

## 먼저 조사할 항목

다음을 코드 수정 전에 조사한다.

1. 전역 CSS 진입점
2. CSS reset 또는 normalize 중복
3. Tailwind preflight와 전역 CSS 충돌
4. CSS Module과 전역 selector 충돌
5. 동일한 CSS 변수 이름의 중복 선언
6. `body`, `button`, `input`, `textarea`에 대한 중복 스타일
7. 컴포넌트 라이브러리의 기본 테마
8. 에디터 라이브러리의 기본 CSS
9. `!important` 사용 위치
10. 지나치게 높은 specificity
11. 페이지별 중복 색상값
12. 사용하지 않는 구형 stylesheet
13. hydration 이후 클래스가 달라지는 부분
14. 모바일 media query 충돌
15. 잘못된 z-index 계층

조사한 뒤 CSS가 깨지는 원인을 실제 코드 기준으로 정리하고 제거한다.

## 재구축 원칙

다음 계층을 사용한다.

```text
Reset
→ Semantic design tokens
→ Base typography
→ Layout primitives
→ Shared components
→ Feature components
→ Page-specific layout
```

권장 파일 구조:

```text
styles/
  reset.css
  tokens.css
  base.css
  layout.css
  editor.css
  utilities.css
```

프로젝트가 Tailwind를 사용한다면 Tailwind를 유지할 수 있다.

다만 다음 기준을 적용한다.

* 반복 색상은 semantic token으로 이동
* 반복 간격은 spacing scale로 통일
* JSX arbitrary value 남발 금지
* 페이지마다 다른 임의 색상 사용 금지
* 동일한 UI에 서로 다른 class 조합 사용 금지
* 기존 CSS를 `!important`로 덮지 않기
* 전역 selector 사용 최소화
* 에디터 라이브러리 스타일은 별도 scope 안에 격리

`!important`는 외부 라이브러리 스타일을 제어할 다른 방법이 없는 경우에만 제한적으로 사용한다.

# 4. 색상 시스템

색상 불일치를 막기 위해 색상 수를 강하게 제한한다.

기본 구조는 다음과 같다.

```text
중립색:
앱 배경, 사이드바, 문서 면, 텍스트, 테두리

주요 포인트 색:
Moodi 브랜드와 주요 동작

감정 색:
작은 상태 표시와 제한된 배경 영역에만 사용
```

## 기본 토큰 출발점

```css
:root {
  color-scheme: light;

  --color-canvas: #f5f5f7;
  --color-sidebar: rgba(246, 246, 248, 0.88);
  --color-surface: #ffffff;
  --color-surface-secondary: #f2f2f4;
  --color-surface-elevated: rgba(255, 255, 255, 0.82);

  --color-text-primary: #1d1d1f;
  --color-text-secondary: #6e6e73;
  --color-text-tertiary: #8e8e93;

  --color-border: rgba(60, 60, 67, 0.12);
  --color-border-strong: rgba(60, 60, 67, 0.2);

  --color-accent: #8a6fa8;
  --color-accent-hover: #765d94;
  --color-accent-soft: rgba(138, 111, 168, 0.12);
  --color-accent-selected: rgba(138, 111, 168, 0.18);

  --color-success: #4f8a66;
  --color-warning: #aa7a35;
  --color-danger: #b6535c;

  --color-backdrop: rgba(0, 0, 0, 0.22);
}
```

이 값은 출발점이며 실제 화면 검수 후 조정할 수 있다.

## 색상 적용 규칙

* 한 화면에서 강한 포인트 색은 기본적으로 한 종류만 사용한다.
* 주요 CTA는 동일한 accent color를 사용한다.
* 선택 상태도 같은 accent 계열을 사용한다.
* 사이드바 활성 항목도 같은 accent 계열을 사용한다.
* 감정 색상을 큰 카드 배경 전체에 무작위로 적용하지 않는다.
* 감정 색상은 점, 작은 아이콘, 얇은 tint, 차트 데이터에 제한한다.
* 페이지별로 주조색이 바뀌지 않는다.
* 모든 카드를 서로 다른 파스텔 색으로 만들지 않는다.
* 순수 검정 대신 부드러운 진회색을 사용한다.
* 콘텐츠 영역은 기본적으로 흰색 또는 매우 옅은 중립색을 사용한다.

## 감정 색상

감정 색상은 다음처럼 낮은 채도로 제한한다.

```css
--mood-calm: #7f9b8a;
--mood-happy: #d19a4f;
--mood-excited: #b6758d;
--mood-neutral: #8d8d93;
--mood-tired: #758ba3;
--mood-complicated: #897ba3;
--mood-sad: #6f88a5;
```

감정 색상은 전체 제품의 브랜드 컬러와 경쟁하면 안 된다.

# 5. 다크 모드

프로젝트에 기존 다크 모드가 안정적으로 구현되어 있다면 semantic token을 기반으로 유지한다.

기존 다크 모드가 깨져 있거나 불완전하다면 이번 작업에서는 라이트 모드 완성도를 먼저 확보한다.

불완전한 다크 모드를 억지로 유지하지 마라.

다크 모드를 구현하는 경우 다음 원칙을 따른다.

* 단순 색상 반전 금지
* 완전한 검정 배경 남용 금지
* 카드와 배경의 층위 유지
* 이미지와 차트 대비 확인
* 감정 색상 채도 조정
* 모든 semantic token에 dark value 제공

# 6. 타이포그래피

Apple 플랫폼에서는 시스템 폰트가 중요한 역할을 하지만, 한국어 웹앱에서는 실제 한글 조판 품질을 우선한다.

기본 폰트는 Pretendard Variable을 사용한다.

Apple 환경에서는 시스템 폰트가 자연스럽게 fallback될 수 있도록 구성한다.

```css
font-family:
  "Pretendard Variable",
  "Pretendard",
  -apple-system,
  BlinkMacSystemFont,
  "SF Pro Text",
  "Segoe UI",
  sans-serif;
```

SF Pro 파일을 프로젝트에 추가하거나 배포하지 마라.

폰트 이름만 선언하고 Pretendard가 실제 로드되지 않는 상태를 허용하지 않는다.

Playwright에서 computed `font-family`와 폰트 네트워크 요청을 확인한다.

## 타이포그래피 스케일

```text
Display:
40~48px / 650 / line-height 1.15

Page title:
30~36px / 650 / line-height 1.22

Document title:
36~44px / 650 / line-height 1.2

Section title:
20~24px / 600 / line-height 1.3

Card title:
17~21px / 600 / line-height 1.4

Body:
16~18px / 400 / line-height 1.65

Journal body:
18~20px / 400 / line-height 1.75~1.85

UI label:
14~15px / 500

Metadata:
13~14px / 400~500
```

## 규칙

* 한 화면에 너무 많은 글자 크기를 사용하지 않는다.
* 작은 회색 글자를 남발하지 않는다.
* 보조 텍스트도 최소한의 가독성을 확보한다.
* 한글에 과도한 자간을 적용하지 않는다.
* 손글씨체나 장식용 명조체를 사용하지 않는다.
* 감성을 폰트 종류보다 조판과 콘텐츠로 표현한다.

# 7. 간격과 레이아웃 토큰

간격은 다음 스케일을 사용한다.

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 20px;
--space-6: 24px;
--space-8: 32px;
--space-10: 40px;
--space-12: 48px;
--space-16: 64px;
```

## 사용 규칙

* 아이콘과 라벨: 8px
* 관련된 작은 요소: 8~12px
* 폼 필드 내부: 12~16px
* 카드 내부: 16~24px
* 카드 사이: 16~24px
* 섹션 사이: 32~48px
* 페이지 상단: 24~40px

모든 섹션에 큰 여백을 일괄 적용하지 않는다.

콘텐츠 관계에 따라 간격을 다르게 사용한다.

# 8. 모서리와 깊이

Apple식 디자인 감성을 표현하기 위해 모든 요소를 둥글게 만들지 않는다.

## Radius

```text
작은 버튼과 입력:
8~10px

팝오버와 메뉴:
12~14px

일반 카드:
14~18px

모달과 큰 패널:
18~22px
```

알약 모양은 다음 요소에만 제한한다.

* 작은 필터
* 감정 선택
* 상태 표시
* 짧은 segmented control

## 그림자

강한 그림자는 사용하지 않는다.

권장 방식:

* 기본 카드: 테두리만 사용
* 떠 있는 메뉴: 약한 그림자
* 모달: 중간 정도의 부드러운 그림자
* 사이드바: 경계선 또는 매우 약한 음영
* hover: 그림자보다 배경색과 border 변화 우선

## 반투명 재질

반투명 효과는 앱의 chrome에만 제한적으로 사용한다.

사용 가능:

* 사이드바
* 모바일 내비게이션
* 상단 바
* 팝오버
* 모달
* floating toolbar

사용 금지:

* 모든 카드
* 일기 본문
* 기록 목록 전체
* 콘텐츠를 읽어야 하는 영역

텍스트 뒤에 blur가 과하게 보이면 실패다.

# 9. 앱 셸

## 데스크톱

ChatGPT와 Notion에서 참고한 접이식 좌측 사이드바를 사용한다.

```text
┌────────────────┬─────────────────────────────────────────┐
│    Sidebar     │              Main content               │
│                │                                         │
│  Moodi         │  Page header                            │
│  새 기록       │                                         │
│                │  Home / Editor / Entries / Calendar     │
│  오늘          │                                         │
│  기록          │                                         │
│  캘린더        │                                         │
│  회고          │                                         │
│                │                                         │
│  최근 기록     │                                         │
│                │                                         │
│  프로필        │                                         │
└────────────────┴─────────────────────────────────────────┘
```

## 사이드바 규격

* 기본 너비: 248~272px
* 접힌 너비: 64~72px
* 전체 높이
* 페이지 콘텐츠와 별도의 카드처럼 뜨지 않음
* 앱 배경과 자연스럽게 연결
* 경계선 또는 약한 material 차이 사용
* 스크롤 가능
* 접기 상태 기억
* 키보드 접근 가능

## 사이드바 항목

상단:

* Moodi 워드마크
* 사이드바 접기
* 새 기록

주요 메뉴:

* 오늘
* 모든 기록
* 캘린더
* 회고

보조 영역:

* 작성 중인 기록
* 최근 기록 3~5개

하단:

* 프로필
* 설정

사이드바에 다음을 넣지 않는다.

* 깊은 폴더 트리
* 과도한 태그 목록
* 감정별 메뉴 전체
* AI 분석 메뉴
* 복잡한 드래그 구조
* 데이터베이스 속성

## 활성 상태

활성 항목은 다음 조합으로 표시한다.

* accent soft background
* 텍스트 굵기 변화
* 아이콘 색상 변화

강한 컬러 막대, 그라데이션, 두꺼운 border는 사용하지 않는다.

# 10. 모바일 앱 셸

모바일에서는 사이드바를 숨긴다.

다음 구조를 사용한다.

* 상단의 간결한 title bar
* 필요한 경우 햄버거 드로어
* 하단 내비게이션
* 중앙 작성 동작

하단 메뉴:

```text
오늘
기록
작성
캘린더
나
```

모바일 하단 내비게이션은 Apple식 material 감각을 절제해서 적용할 수 있다.

* 반투명한 중립색 배경
* 얇은 상단 경계
* 안전 영역 대응
* 콘텐츠를 가리지 않는 높이
* 활성 탭에 하나의 accent 사용

모바일에서 데스크톱 사이드바를 단순히 오버레이하는 것으로 끝내지 않는다.

# 11. 홈 화면

홈 화면은 ChatGPT의 깔끔한 시작 화면과 Apple 제품의 콘텐츠 중심 구성을 참고한다.

대시보드 카드 모음으로 만들지 않는다.

## 구조

1. 날짜와 짧은 인사
2. 오늘 기록하기
3. 빠른 기분 기록
4. 작성 중인 기록
5. 최근 기록
6. 과거의 오늘 또는 오늘의 질문

## 상단

```text
7월 14일, 화요일

오늘은 어떤 하루였어?
```

주요 동작:

```text
새 일기 작성
```

보조 동작:

```text
기분만 남기기
```

상단 영역은 지나치게 큰 랜딩 히어로가 아니어야 한다.

데스크톱에서 약 240~340px 안에 자연스럽게 구성한다.

## 최근 기록

첫 번째 기록을 적당히 강조하되 거대한 감성 카드로 만들지 않는다.

* 제목
* 본문 2~4줄
* 날짜
* 감정
* 대표 이미지

나머지 기록은 간결한 목록 또는 작은 프리뷰로 표시한다.

## 색상

홈 화면에는 브랜드 accent 하나만 주요 색상으로 사용한다.

최근 기록 이미지와 감정 표시는 보조 색상으로 취급한다.

홈 화면에서 로즈, 피치, 라벤더, 세이지를 동시에 노출하지 않는다.

# 12. 에디터

에디터는 Notion의 문서 작성 경험을 참고하되, Moodi에 필요한 기능만 제공한다.

* 선택적 커버
* 날짜
* 제목
* 감정과 에너지
* 본문 블록
* 이미지
* 태그
* 자동 저장
* Moodi 질문

```text
680~760px

넓은 이미지:
최대 960px

에디터 외곽 작업 영역:
최대 1200px
```

본문은 화면 중앙에 배치하되 좌우 공간이 지나치게 비어 보이지 않게 한다.

## 블록

지원:

* 문단
* 제목 1
* 제목 2
* 제목 3
* 글머리 목록
* 번호 목록
* 체크리스트
* 인용문
* 구분선
* 이미지
* 이미지 캡션
* Moodi 질문

지원하지 않음:

* 코드
* 데이터베이스
* 칸반
* 테이블
* 수식
* 개발자용 embed

## Slash 메뉴

`/` 입력 시 커서 근처에 메뉴를 표시한다.

메뉴는 중립색 표면을 사용한다.

accent 색상은 선택된 항목에만 사용한다.

메뉴 항목:

```text

큰 제목
작은 제목
사진
인용문
체크리스트
구분선
Moodi 질문
```

기술 용어를 사용자에게 노출하지 않는다.

## Bubble toolbar

텍스트 선택 시에만 표시한다.

* 굵게
* 기울임
* 밑줄
* 취소선
* 링크
* 하이라이트

검은색 Notion 툴바를 그대로 복제하지 않는다.

밝은 neutral material과 accent selection을 사용한다.

메타데이터를 항상 여러 줄로 펼쳐두지 않는다.

에디터가 폼처럼 보이지 않아야 한다.

# 14. 기록 목록

기록 목록은 ChatGPT의 대화 기록 탐색과 Notion의 문서 목록을 참고하되 일기 콘텐츠를 충분히 보여준다.

## 구조

* 상단 제목과 검색
* 접힌 필터
* 날짜 기준 그룹
* 기록 목록

각 기록:

* 날짜
* 제목
* 본문 2~3줄
* 대표 이미지
* 감정 표시
* 태그 최대 2개

## 스타일

한 종류의 중립색 카드 또는 구분선 기반 목록을 사용한다.

모든 기록에 서로 다른 배경색을 사용하지 않는다.

강조가 필요한 기록만 다음 중 하나를 사용할 수 있다.

* 대표 이미지
* accent tint
* 즐겨찾기 표시

테이블, 칸반, masonry와 복잡한 보기 전환은 사용하지 않는다.

# 15. 기록 상세

기록 상세는 읽기 경험을 최우선으로 한다.

순서:

1. 날짜
2. 제목
3. 감정과 메타데이터
4. 대표 이미지
5. 본문

7. Moodi가 남긴 한마디
8. 관련 과거 기록
9. 수정과 삭제

본문은 에디터와 동일한 타이포그래피 체계를 사용한다.

편집과 읽기 모드가 서로 다른 제품처럼 보이지 않아야 한다.

`Moodi가 남긴 한마디`는 accent soft 배경을 사용하되, 다른 감정 색상을 추가하지 않는다.

AI 영역은 최대 3~5문장이다.

# 17. 캘린더

캘린더는 Apple 캘린더처럼 명확하고 차분한 정보 계층을 가진다.

* 월 제목
* 이전·다음
* 오늘
* 요일
* 날짜
* 기록 표시
* 선택한 날짜의 기록

날짜 셀에는 다음만 표시한다.

* 날짜
* 작은 감정 점 또는 기록 점

셀마다 색상 배경을 채우지 않는다.

선택 상태는 accent soft background로 표시한다.

선택한 날짜의 기록은 캘린더 아래에 중립적인 기록 프리뷰로 보여준다.

# 18. 회고

회고는 통계 대시보드가 아니라 하나의 정돈된 리포트처럼 구성한다.

순서:

1. 이번 주를 표현하는 문장
2. 감정 흐름 차트
3. 자주 등장한 주제
4. 관련 기록
5. Moodi가 남긴 한마디

차트는 semantic mood colors를 사용할 수 있다.

단, 페이지의 기본 UI 색상과 차트 색상을 혼합하지 않는다.

통계 카드 격자를 사용하지 않는다.

# 19. 설정

설정은 Apple 설정 화면의 명확한 그룹 구조를 참고한다.

그룹:

* 계정
* 화면
* 일기
* AI 도움
* 개인정보와 데이터

설정 항목은 목록과 구분선 중심으로 구성한다.

모든 설정을 개별 카드로 만들지 않는다.

위험한 동작은 별도 그룹에 배치한다.

# 20. 아이콘

아이콘은 프로젝트에 이미 일관된 라이브러리가 있다면 이를 사용한다.

없다면 하나의 아이콘 라이브러리를 선택한다.

여러 아이콘 세트를 섞지 않는다.

규칙:

* 기본 크기 18~20px
* stroke 두께 일관성 유지
* 텍스트와 함께 사용
* 의미 없는 장식 아이콘 금지
* Apple SF Symbols를 복사하거나 파일로 포함하지 않음
* emoji를 UI 아이콘 대신 사용하지 않음

---

# 21. 모션

Apple식 감성을 단순한 blur가 아니라 모션 품질로 표현한다.

지원:

* 사이드바 접기와 펼치기
* 팝오버 등장
* 모달과 바텀시트
* 페이지 전환
* 선택 상태 변화
* 자동 저장 상태
* 블록 삽입

기준:

```text
짧은 상태 변화:
120~180ms

팝오버와 메뉴:
160~220ms

사이드바와 모달:
220~320ms
```

금지:

* bounce 남발
* glow
* parallax
* 긴 fade
* 강한 spring
* 모든 요소에 애니메이션 적용

`prefers-reduced-motion`을 지원한다.

# 22. 상태와 피드백

Apple식 인터페이스처럼 상태를 작고 명확하게 표시한다.

자동 저장 상태:

* 저장 중
* 저장됨
* 오프라인
* 저장 실패

과도한 toast를 사용하지 않는다.

성공 상태는 조용하게 표시한다.

오류 상태는 구체적인 해결 행동과 함께 제공한다.

# 26. 시각적 반복 검수

첫 번째 구현으로 종료하지 않는다.

다음 과정을 최소 두 차례 수행한다.

```text
현재 화면 캡처
→ CSS와 색상 문제 분석
→ 구조와 토큰 수정
→ 동일 viewport 재촬영
→ 이전 화면과 비교
→ 추가 수정
```

스크린샷 저장 예시:

```text
artifacts/ui-review/
  before/
  iteration-1/
  iteration-2/
  final/
```

필수 최종 화면:

* 홈 데스크톱
* 홈 모바일
* 에디터 데스크톱
* 에디터 모바일
* Slash 메뉴
* 기록 목록
* 기록 상세
* 캘린더
* 회고
* 설정
* 펼친 사이드바
* 접힌 사이드바

스크린샷 파일을 생성하는 것으로 끝내지 않는다.

실제로 이미지를 열고 다음을 확인한다.

* 색상이 서로 충돌하지 않는가
* 같은 의미의 UI가 같은 색을 사용하는가
* 브랜드 accent가 일관적인가
* 감정 색이 브랜드색과 경쟁하지 않는가
* neutral background의 층위가 명확한가
* 사이드바와 메인 영역이 자연스럽게 이어지는가
* 화면이 Apple 제품처럼 정돈되어 보이는가
* Notion 또는 ChatGPT의 복제품처럼 보이지 않는가
* Moodi의 개인적인 일기 성격이 남아 있는가

# 27. 기존 코드 제거 기준

다음 코드는 제거하거나 교체한다.

* 여러 아이콘 라이브러리
* 깨진 반응형 media query
* 사용하지 않는 UI 컴포넌트
* 서로 다른 카드 구현
* 반복되는 버튼 구현
* 기존 색상 테마 잔재
* 높은 specificity의 구형 selector

기존 CSS 파일이 남아 새 스타일에 영향을 줄 가능성이 있다면 삭제 또는 import 제거를 수행한다.

단, 사용자 데이터와 비즈니스 로직을 삭제하지 않는다.

# 30. 성공 조건

다음 조건을 모두 충족해야 Goal 완료를 선언한다.

## CSS

* 기존 스타일 충돌 원인이 제거됨
* 중복 reset과 중복 token이 없음
* 불필요한 `!important`가 없음
* 디자인 토큰이 단일 진실 공급원으로 사용됨
* 페이지별 색상 하드코딩이 제거됨
* 모든 주요 화면에서 CSS가 깨지지 않음
* 모바일 overflow가 없음
* 팝오버와 모달이 viewport 밖으로 나가지 않음

## 디자인

* ChatGPT·Notion형 접이식 사이드바가 있음
* 사이드바가 IDE처럼 보이지 않음
* 우측 고정 패널이 없음
* Apple식 절제, 계층과 재질감이 느껴짐
* 강한 브랜드 accent는 하나만 사용함
* 감정 색상은 보조 요소로 제한됨
* 페이지마다 색이 제각각이지 않음
* 카드가 모두 다른 색이 아님
* 텍스트와 실제 기록이 중심임
* 지나치게 밋밋하지 않음
* 지나치게 장식적이지 않음
* ChatGPT, Notion 또는 Apple의 복제품으로 보이지 않음
* Moodi의 따뜻하고 개인적인 인상이 유지됨
